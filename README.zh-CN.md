## 项目简介

这是对 **Angels Online** 网络协议的逆向记录，以及能使用该协议通信的服务端。原文介绍的 IGG 游戏于 2026 年 2 月关闭，最早提到的客户端版本为 8.5.1.0；实现依据是客户端文件和网络流量抓包。

**这不是完整模拟器。** 它由已记录的协议和逐步实现的服务端组成：可以创建角色、完成教学、选择职业、打怪、升级、在商店买卖。尚未完成的部分会明确列出，不作完整还原的承诺。

原文强调：协议结论应有测量依据；猜测必须标为猜测。

### 为什么需要第二个服务器

地图从 patch25 起就在客户端里。Niro River 门通向它，但原主服只发送 7 个挤在 `(1..6,1..5)` 角落的 NPC，说明地图有声明却无内容。因此门先标记关闭，等待有内容的版本。

第二个服务器穿过同一门会发 171 个分布全图、包含真实怪物的实体。缺的是服务器内容，不是地图文件。

### 取了什么、没取什么

原则是**只取数据，不直接搬原始字节**。两版本 `0x0008` 出生消息均为 63 字节、字段位置相同，移动请求也相同，所以能共用解码。

不同之处：换图 `0x000C` 为 20 字节且不含 IP 字符串，地图号仍在偏移 0，目的端口位置不同；当时还出现未知的 `0x018A`（多为 8 字节）、空体 `0x006D`、单字节 `0x0142`。这些是该段调查时的未知状态。

名称使用 Big5，不是英文；通过一致的 `npc_type` 与英文 `content.db` 匹配，无需人工翻译。

### 两项工具变化

`tools/separar_por_mapa.py` 按同会话内的换图分割抓包，避免把多个地图对象误放同一模板。以前某服务器每次换图开新连接，单文件自然只有一图；新服务器一个连接可走六图。

`tools/poblar_mapa.py` 从 ASCII 改为兼容 ASCII 的 Big5 解码，再按 NPC ID 配回英文名称。

## 运行方法

原项目要求 Python 3.10+ 和客户端。原文测试版是 8.7.6.1，抓包基础为 8.6.0.8；项目声称这两个定制版本关键协议一致，**不能推广为任意地区客户端都兼容**。

原文提供的客户端：[8.7.6.1 下载](https://drive.google.com/file/d/1SDckJV2GFD2-lyHQ_3sgtJrB2PjROyWg/view?usp=sharing)。这是 IGG 基础上移植台服 update32 并翻译成英文的版本；后续通过正常 START.EXE 从服务端更新。此处仅保留原链接，未重新验证可下载性。

1. 把客户端 `server.xml` 指向本机：

   ```xml
   <伺服器 名稱="Local" 編號="16" 選擇="100"
           ip="127.0.0.1" port="16768" 分流="2"
           fip="127.0.0.1" fport="21238" />
   ```

2. 原项目启动入口：

   ```text
   ./correr_servidor.sh        # Linux / macOS / Git Bash
   correr_servidor.bat         # Windows
   ```

3. 打开客户端用新用户名登录，会自动建账号；密码按当前验证规则保存和检查。

**本机请使用项目根目录的 `start-local.bat` 或 `start-local.ps1`**，它们带中文客户端协议/语言配置。已有服务端时不要重复启动。正常退出角色后再停服，避免未保存的内存进度丢失。

**跳过客户端更新器：**先启动服务端，再双击 `D:\天使之恋Online\启动客户端.bat`。脚本直接执行同目录的 `angel.dat`，并将工作目录设为客户端目录，不经过 `START.EXE`，不改动游戏文件、账号或服务器地址。因为 `angel.dat` 实际是 Windows 可执行文件，脚本使用直接进程启动，而不是依赖 `.dat` 文件关联；无需改名为 `.exe`。此方式不会执行启动器的更新流程，需要更新客户端资源时应另行处理。

所有会话录制在 `logs/sesiones/`，供排错。

## 藏在客户端中的四张表

曾对四个系统猜测多日，最终发现数据就在 PAK 中，不需凭空拟合公式。

**`pet.xml`：1751 种宠物。** 造型、类型 ID、名字、属性类别、进化阶段及两条分支。过去类型 ID 发 0 导致窗口无等级/图像；捕获的 13 对造型/类型均匹配。

**`petaspect.xml`：培养事件。** 107 种，每种三选项，分值 -3～+3；文本与游戏一致。

**`jeweleffect.xml`：宝石效果。** 870 行；数值在宝石本体，表决定镶到什么部位时加什么属性。同一符文放武器加法攻、放防具加法防。

## 有意省略的内容

原文为简化本机运行，不做正式注册流程。它早期写“无需数据库”、账户保存在 JSON，并给手改 JSON 示例；后面已更新成 SQLite 密码验证。

> 译者核对：**当前真源是 `data/cuentas.db`，JSON 只是镜像。不要把下面的历史示例覆盖到现有存档，也不要靠编辑 JSON 改角色。**

历史 JSON 结构示例：

```json
{
  "cuentas": {
    "youruser": {
      "password": "whatever",
      "personajes": []
    }
  }
}
```

密码会验证且可关闭：客户端发 32 字节密码摘要，服务端在 SQLite 加盐保存。数据库 `configuracion` 表开关下次登录生效，不需重启：

| 键 | 默认 | 含义 |
| --- | --- | --- |
| `validar_password` | 1 | 1 检查密码，0 跳过检查 |
| `registrar_primer_hash` | 1 | 无密码的账号记录首次摘要；0 则拒绝 |
| `reemplazar_contrasena` | 0 | 1 时错误密码变成新密码而不是拒绝；改密后必须恢复 0 |
| `guardar_auth_crudo` | 0 | 1 保存完整认证报文，包含敏感认证数据 |

原文示例 `UPDATE configuracion SET valor='0' WHERE clave='validar_password';` 是**关闭密码验证**，不是推荐设置；本次没有执行。

没有注册网页、邮箱、找回密码；它定位是本地服务端。
